# Architecture Decision Records

## 철학
MVP 속도 최우선. 오버엔지니어링 금지 — 최소 변화로 최대 아웃풋. 외부 의존성과 추상화 계층을 최소화하고, 작동하는 최소 구현을 선택한다. 사용자가 확정한 기능은 줄이지 않되, 복잡도는 줄인다.

---

### ADR-001: 이미지 모델 `gpt-image-2`
**결정**: OpenAI `gpt-image-2`(스냅샷 `gpt-image-2-2026-04-21`)를 쓴다.
**이유**: 입력 이미지 다중 편집(`images.edit`), n 변형, 유연 해상도(1280×720 직접 생성)를 모두 지원해 요구에 정확히 맞는다.
**트레이드오프**: DALL·E 3 대비 신규 모델 — 조직 인증/권한이 필요할 수 있음.

### ADR-002: API 키 서버 전용 + Route Handler 경유
**결정**: `OPENAI_API_KEY`와 OpenAI 호출은 `src/app/api/**`에서만. 클라 직접 호출 금지.
**이유**: 키 유출 방지.
**트레이드오프**: 브라우저→서버 왕복 1회 추가.

### ADR-003: 입력 이미지 유무로 edit/generate 분기
**결정**: 업로드 이미지≥1이면 `images.edit`(다중 `image` 배열), 없으면 `images.generate`.
**이유**: 한 진입점에서 두 사용 사례를 단순하게 커버.
**트레이드오프**: 분기 로직 한 줄 추가.

### ADR-004: 제목은 클라이언트 canvas 오버레이(고정 스타일)
**결정**: 제목 텍스트는 AI가 아니라 브라우저 canvas로 합성. MVP는 하단 스크림+외곽선+자동 폰트 크기 고정.
**이유**: 글자 철자 100% 정확, API 비용 없이 즉시 재렌더. 위치/색 컨트롤은 후순위(스코프 절감).
**트레이드오프**: 텍스트 배치 자유도 낮음(후속 step에서 확장 가능).

### ADR-005: 1280×720 직접 생성
**결정**: gpt-image-2 유연 해상도로 유튜브 규격 1280×720을 바로 생성. 크롭 단계 없음.
**이유**: 파이프라인 단순화(서버/클라 크롭 로직 제거).
**트레이드오프**: 더 선명한 결과가 필요하면 추후 2560×1440 생성→다운스케일로 확장.

### ADR-006: 후보 n:3 · quality medium
**결정**: 한 번에 3장 생성, 퀄리티 medium 고정.
**이유**: 선택지 제공 ↔ 비용/속도 균형.
**트레이드오프**: 후보 수만큼 과금. 비용 민감 시 추후 `n` 옵션화.

### ADR-007: 에러 4코드 정규화(mapError, route 인라인)
**결정**: 업스트림 예외를 `INVALID_INPUT`/`CONTENT_POLICY`/`RATE_LIMITED`/`UPSTREAM_ERROR`로 정규화. UI는 코드만 보고 렌더.
**이유**: 사용자 행동이 갈리는 최소 분류만 유지(8코드 → 4코드). UI/메시지 결합도 낮춤.
**트레이드오프**: 세부 원인(예: 401 vs 500)은 UPSTREAM으로 합쳐져 사용자에겐 구분 안 됨(개발 로그로 확인).

### ADR-008: 후보는 webp 응답, 최종 PNG는 클라 생성
**결정**: 후보 3장은 `output_format:"webp"`로 받아 페이로드를 줄이고, 다운로드 PNG는 canvas가 생성.
**이유**: 3×1280×720 base64 PNG는 JSON 페이로드가 과도. webp로 3~5배 절감.
**트레이드오프**: 미리보기와 최종 포맷이 다름(미리보기 webp, 다운로드 PNG) — 품질 차이는 무시 가능.

### ADR-009: 린 구조 — services/lib 모듈 미선반영
**결정**: 호출처 1곳인 OpenAI 호출/검증/에러매핑은 route.ts에 인라인. 별도 모듈 미생성.
**이유**: 조기 추상화 회피(YAGNI). route.ts가 120줄 초과 시에만 `services/openai.ts` 추출.
**트레이드오프**: route.ts가 다소 길어질 수 있음 — 임계치에서 리팩터링으로 대응.
